# Dream Machine Edge Contract v1

- **Status**: Proposed
- **Date**: 2026-09-04
- **Owning decision**: [ADR-0101](../../adrs/ADR-0101-uno-q-ruview-home-core-runtime.md)
- **Compatibility target**: Arduino UNO Q Debian and STM32U585, RuView HOMECORE, RuVector, local MCP clients

This document defines the first stable boundary between adaptive Dream Machine
software and a safety controller that can operate physical outputs. It is a
contract and test plan, not evidence that the hardware integration already
exists or meets its targets.

The architecture pull request freezes only the executable schemas and registry
present in this directory. The remaining interfaces are normative design input
but are not implementation-ready until PR 2 adds their schemas, numeric CBOR
registries, semantic validators, and golden vectors. No current code may claim
Edge Contract v1 conformance.

The terms MUST, MUST NOT, REQUIRED, SHOULD, SHOULD NOT, and MAY are normative.
All quantitative values are provisional v1 limits or acceptance targets. A
measured claim requires a committed evidence report and the artifact hashes
listed in ADR-0101.

## 1. Invariants

1. A model, agent, MCP client, HOMECORE automation, and signed Wasm plugin can
   create a `CueProposalV1`. None can create an actuator transition.
2. Only the isolated cue broker can issue a `CueTicketV1`.
3. Only the STM32 safety controller can open an output gate.
4. The STM32 independently checks identity, boot, firmware, policy, consent,
   signature, sequence, time, modality, asset, intensity, duration, ramp,
   cooldown, cumulative budget, arm state, and health before actuation.
5. Any unknown, missing, malformed, stale, ambiguous, or out of range value
   fails closed.
6. DISARMED, MUTED, FAULT, reboot, watchdog expiry, and broker heartbeat loss
   mean every output is off.
7. A safe action such as mute may bypass convenience layers. An unsafe action
   such as arm, resume, policy replacement, or firmware installation never may.
8. Raw bedroom signals, private journal content, and signing material are not
   exposed through MCP.
9. Missing memory, models, network, clock synchronization, or optional sensors
   degrades to observation or abstention. It never broadens authority.

## 2. Common representation rules

### 2.1 Identifiers and time

| Field kind | Binary form | JSON and MCP form | Rule |
|---|---|---|---|
| `deviceId`, `bootId`, `ticketId`, `receiptId`, `decisionId`, `proposalId`, `candidateId`, `challengeId`, `experimentId` | 16 byte string | 32 lowercase hexadecimal characters | Generated from a cryptographically secure source; all zero is invalid |
| SHA 256 digest | 32 byte string | 64 lowercase hexadecimal characters | Content address of the exact artifact bytes |
| Sequence | unsigned 64 bit integer | Base 10 string | Strictly increasing within its documented boot scope |
| Monotonic time | unsigned 64 bit integer in microseconds | Base 10 string | Never interpreted as wall clock time |
| Wall time | Not used for safety decisions | RFC 3339 string ending in `Z` | Informational and audit use only |
| Confidence and normalized intensity | unsigned Q15 integer, 0 through 32767 | Integer, 0 through 32767 | No floating point in the MCU protocol |

JSON uses strings for unsigned 64 bit values because JSON numbers cannot
portably preserve the full integer range. Every schema declares its unit. A
consumer MUST NOT infer a unit from a field name alone.

### 2.2 Versioning

Every structure begins with `schemaVersion`. A v1 MCU message has an exact key
set. The MCU MUST reject unknown keys, duplicate keys, missing keys, tags,
indefinite length items, floating point values, negative unsigned fields, and
an encoded value larger than the type limit.

Additive data plane fields require a new schema version when the strict MCU
parser receives them. MCP resource JSON may add optional display metadata only
when the JSON Schema allows it. A change in safety meaning, units, signature
coverage, modality mapping, or authority always requires a new major contract.

### 2.3 Evidence level

All derived data carries one of these values:

| Level | Meaning |
|---|---|
| `simulated` | Generated by a deterministic fake or replay fixture |
| `transport_verified` | Real bytes crossed the intended adapter, but sensing accuracy was not independently measured |
| `fixture_measured` | An independent hardware fixture measured timing or output |
| `human_reference_measured` | A consented comparison used an independent human reference sensor |
| `promoted` | A human accepted the evidence and signed the release or policy |

The system MUST NOT relabel simulated or transport verified data as measured.

## 3. SignalFrameV1

`SignalFrameV1` is the normalized input to HOMECORE, RuVector, the learner, and
the cue broker. Source adapters may add source specific values inside `values`,
but the envelope is stable.

The executable JSON projection is
[`observation.schema.json`](./observation.schema.json). The schema is canonical
for JSON field names and types; generated language bindings must not redefine
it by hand.

```ts
export interface SignalFrameV1 {
  schemaVersion: 1;
  sourceId: string;
  sourceKind: "mr60bha2" | "esp32_csi" | "ambient" | "watch";
  bootId: string;
  sequence: string;
  observedAt: string;
  sourceMonotonicUs: string;
  ingestedMonotonicUs: string;
  clockUncertaintyMs: number;
  qualityQ15: number;
  flags: SignalFlagV1[];
  values: Record<string, number | boolean | null>;
  evidenceLevel: "simulated" | "transport_verified" |
    "fixture_measured" | "human_reference_measured" | "promoted";
  privacyClass: "P0" | "P1" | "P2" | "P3";
  rawRef?: string;
  provenance: {
    adapter: string;
    adapterVersion: string;
    calibrationId: string;
    inputDigest: string;
  };
}
```

`observedAt` is informational UTC wall time. Safety code uses the monotonic
fields. `rawRef`, when present during an explicitly consented calibration,
uses `urn:dream-machine:calibration:{sha256}` and is not an MCP resource.

### 3.1 Signal flags

The initial flag vocabulary is:

`no_presence`, `out_of_geometry`, `low_snr`, `interference`, `packet_loss`,
`clock_uncertain`, `sensor_warmup`, `stale`, `restarted`, `calibration_needed`,
`multiple_subjects`, and `source_fault`.

Unknown source conditions map to `source_fault` and a source specific audit
detail. They do not silently disappear.

### 3.2 MR60BHA2 values

The radar adapter may publish:

| Key | Unit | Value |
|---|---|---|
| `presence` | Boolean | Bounded presence state |
| `distance_m` | Metres | Estimated distance or `null` |
| `respiration_bpm` | Breaths per minute | Estimate or `null` |
| `heart_bpm` | Beats per minute | Estimate or `null` |
| `total_phase` | Upstream module unit | Optional calibration value |
| `respiration_phase` | Upstream module unit | Optional calibration value |
| `heart_phase` | Upstream module unit | Optional calibration value |

The adapter MUST record module firmware identity and effective serial settings
in the device status resource. It MUST NOT convert a missing estimate to zero.
It MUST mark out of geometry data rather than extrapolating beyond the sensor's
documented installation envelope.

### 3.3 CSI values

Raw CSI format remains owned by RuView. Dream Machine MUST consume a pinned,
versioned RuView envelope instead of creating a competing CSI payload format.
The minimum metadata accepted by the edge adapter is node identifier, node boot
identifier, source sequence, transmitter timestamp or TSF when available,
channel metadata, payload length, integrity check, and firmware digest.

CSI uses UDP directly to the Debian ingest service. The adapter MUST quantify
loss, reorder, duplicate frames, and clock uncertainty. It MUST NOT send bulk
CSI through Arduino Router.

### 3.4 Storage

Raw radar and CSI persistence is off by default. A calibration profile MAY
enable a volatile ring buffer for at most five minutes. Persisting that buffer
requires an explicit local consent event with an expiry and purpose. Normal
operation stores derived features, confidence, flags, calibration identity,
policy evidence, and receipts on an encrypted local volume.

## 4. CueProposalV1

A proposal is untrusted advisory data. It cannot cross the Arduino Router
actuator method and it does not contain a signature.

The executable JSON projection is
[`cue-proposal.schema.json`](./cue-proposal.schema.json).

```ts
export interface CueProposalV1 {
  schemaVersion: 1;
  proposalId: string;
  profileId: string;
  experimentId: string;
  modality: "audio" | "light" | "haptic";
  assetSha256: string;
  intensityQ15: number;
  durationMs: number;
  rampMs: number;
  earliestMonotonicUs: string;
  latestMonotonicUs: string;
  stateDigest: string;
  signalConfidenceQ15: number;
  objective: string;
  reasonCode: string;
  modelDigest: string;
  createdBy: string;
  authority: "none";
}
```

The cue broker MUST rederive every safety relevant value. It MUST NOT trust a
proposal's confidence, state digest, timing, or declared objective without
matching them to its own read only state snapshot. Free text never enters a cue
ticket. `proposalId` and `experimentId` use the 128 bit identifier encoding.
`earliestMonotonicUs` MUST be lower than `latestMonotonicUs`; both are in the
broker's current estimate of the MCU clock domain and are rejected when the
active clock challenge cannot bound their uncertainty.

## 5. SafetyPolicyV1

The policy is a human approved, content addressed artifact in the signed
release bundle. JSON policy bytes use RFC 8785 canonical JSON before SHA 256 is
calculated. The policy includes:

1. Device and profile identities.
2. Cue issuer Ed25519 public key.
3. Firmware allowlist.
4. Physical arm requirements and consent epoch rules.
5. Per modality asset allowlists.
6. Per modality intensity, duration, ramp, cooldown, rolling window, and
   cumulative limits.
7. Required signal sources, minimum quality, maximum clock uncertainty,
   abstention rules, and quiet periods.
8. Experiment identifiers, allocation logic, outcome definitions, and stop
   rules.
9. Data classes, retention, and export permissions.

The learner cannot write the active policy. Policy installation uses a separate
maintenance command, requires a signed bundle and physical confirmation, and
never occurs during an armed session.

## 6. CueTicketV1

### 6.1 Encoding

The ticket is an RFC 8949 deterministic CBOR map with unsigned integer keys.
The maximum encoded size is 768 bytes. The map has exactly the following keys:

| Key | Field | CBOR type | Size or constraint |
|---:|---|---|---|
| 0 | `version` | unsigned integer | Exactly 1 |
| 1 | `ticketId` | byte string | 16 bytes, nonzero |
| 2 | `proposalSha256` | byte string | 32 bytes, digest of RFC 8785 canonical `CueProposalV1` JSON |
| 3 | `deviceId` | byte string | 16 bytes, exact device match |
| 4 | `bootId` | byte string | 16 bytes, current MCU boot only |
| 5 | `challengeId` | byte string | 16 bytes, recent MCU clock challenge |
| 6 | `policySha256` | byte string | 32 bytes, active policy match |
| 7 | `firmwareSha256` | byte string | 32 bytes, running firmware match |
| 8 | `experimentId` | byte string | 16 bytes, active experiment match |
| 9 | `consentEpoch` | unsigned integer | 1 through 2^32 minus 1; zero is invalid |
| 10 | `sequence` | unsigned integer | 64 bit, strictly increasing |
| 11 | `issuedMonotonicUs` | unsigned integer | 64 bit in MCU clock domain |
| 12 | `notBeforeMonotonicUs` | unsigned integer | 64 bit in MCU clock domain |
| 13 | `expiresMonotonicUs` | unsigned integer | 64 bit in MCU clock domain |
| 14 | `stateDigest` | byte string | 32 bytes |
| 15 | `confidenceQ15` | unsigned integer | 0 through 32767 |
| 16 | `modality` | unsigned integer | 1 audio, 2 light, 3 haptic |
| 17 | `assetSha256` | byte string | 32 bytes, policy allowlist match |
| 18 | `intensityQ15` | unsigned integer | 0 through 32767 and policy bound |
| 19 | `durationMs` | unsigned integer | 1 through 60,000 ms and policy bound |
| 20 | `rampMs` | unsigned integer | 0 through 10,000 ms, no greater than duration, and policy bound |
| 21 | `reasonCode` | unsigned integer | 16 bit registered code |
| 22 | `consentSha256` | byte string | 32 bytes, exact active consent record match |
| 23 | `signature` | byte string | 64 byte Ed25519 signature |

The Ed25519 signature covers the deterministic CBOR encoding of the exact map
with keys 0 through 22. The signature key is unavailable to the model process,
MCP server, HOMECORE plugins, asset renderer, and WebUI.

[`safety-decision.schema.json`](./safety-decision.schema.json) defines the JSON
audit representation of the broker decision and this complete ticket. The
signature still covers the deterministic CBOR bytes, not a reserialized JSON
object. An authorized decision carries the signed ticket and MUST NOT duplicate
proposal, consent, policy, or firmware digests in its outer JSON object. A denied
decision has no ticket and carries those four outer digests for audit context.
This representation removes any second value that could contradict an
authorized ticket.

### 6.2 Time and replay

The following relations are REQUIRED:

```text
issuedMonotonicUs <= notBeforeMonotonicUs
notBeforeMonotonicUs < expiresMonotonicUs
expiresMonotonicUs - issuedMonotonicUs <= 2_000_000
```

The MCU supplies `bootId` at startup and issues a single use `challengeId` with
its monotonic time through `dream.edge.v1.time.challenge`. The broker estimates
offset and uncertainty from the bounded request and response interval. A ticket
is valid only for a recent, unconsumed challenge whose uncertainty is within
policy. A reboot changes `bootId`, invalidating every previous challenge and
ticket without relying on wall time. The MCU records the highest accepted
sequence for the current boot and rejects any equal or lower sequence. A ticket
identifier is also held in a bounded recent set until the boot ends.

### 6.3 Verification order

The MCU performs checks in this order so cheap structural failures occur before
cryptographic work while no failure can reach an output:

1. Enforce message length and exact deterministic CBOR structure.
2. Match version, device, boot, challenge, firmware, policy, experiment,
   consent digest, and consent epoch.
3. Verify the Ed25519 signature and proposal digest binding.
4. Validate MCU monotonic time, clock uncertainty, and future horizon.
5. Validate sequence, challenge, and ticket identifier replay state.
6. Require a fresh, unambiguous MCU safety-sensor snapshot above the policy's
   quality floor.
7. Require physical ARMED state, healthy broker heartbeat, and no latched
   fault.
8. Match asset and every modality parameter to the immutable policy.
9. Check cooldown and rolling cumulative budget.
10. Schedule the gate on an MCU hardware timer.
11. Record a receipt, then update replay and dose state atomically.

If persistent dose state cannot be read with integrity, the MCU enters FAULT.
It does not reset the budget to zero.

## 7. CueReceiptV1

Every ticket submission produces a receipt, including structural and policy
rejections when a ticket identifier can be safely recovered.

```ts
export interface CueReceiptV1 {
  schemaVersion: 1;
  receiptId: string;
  ticketId: string | null;
  ticketSha256: string;
  proposalSha256: string | null;
  deviceId: string;
  bootId: string;
  challengeId: string | null;
  sequence: string | null;
  receiptSequence: string;
  decision: "accepted" | "rejected" | "cancelled" | "completed";
  reason: CueReceiptReasonV1;
  receivedMonotonicUs: string;
  scheduledMonotonicUs: string | null;
  gateOpenedMonotonicUs: string | null;
  gateClosedMonotonicUs: string | null;
  policySha256: string;
  firmwareSha256: string;
  assetSha256: string | null;
  armState: "DISARMED" | "OBSERVE" | "ARMED" | "MUTED" | "FAULT";
  evidenceLevel: "transport_verified" | "fixture_measured" | "promoted";
  previousReceiptSha256: string | null;
  mcuSigningKeyId: string;
  signature: string;
}
```

The receipt is an RFC 8949 deterministic CBOR map. Integer keys 0 through 22
correspond exactly to the fields above in declaration order, excluding
`signature`; key 23 is `signature`. The Ed25519 signature covers the map with
keys 0 through 22. `ticketSha256` is the digest of the exact submitted ticket
bytes, including its signature. `receiptSequence` increases strictly within an
MCU boot. `previousReceiptSha256` is null for the first receipt after boot and
otherwise equals the digest of the exact preceding signed receipt bytes.
`mcuSigningKeyId` identifies the MCU receipt public key pinned by the installed
signed bundle. A verifier rejects a bad signature, key, sequence, boot, ticket
digest, or chain link and never repairs a broken chain.
The JSON audit projection encodes `signature` as exactly 86 unpadded base64url
characters representing 64 bytes.

The initial reason vocabulary includes `ok`, `malformed`, `unsupported_version`,
`identity_mismatch`, `boot_mismatch`, `firmware_mismatch`, `policy_mismatch`,
`experiment_mismatch`, `consent_revoked`, `signature_invalid`, `too_early`,
`expired`, `horizon_exceeded`, `replay`, `not_armed`, `heartbeat_lost`, `fault`,
`asset_denied`, `intensity_denied`, `duration_denied`, `ramp_denied`,
`cooldown`, `dose_budget`, `low_signal_quality`, `cancelled_by_user`, and
`internal_error`.

An authenticated MCU receipt is evidence that the identified firmware recorded
the commanded gate state and its timestamps. It does not prove physical sound
pressure, lux, acceleration, or an uncompromised MCU. Only the independent HIL
witness may raise those measurements to `fixture_measured`.

## 8. STM32 state machine

| State | Outputs | Entry | Exit |
|---|---|---|---|
| `DISARMED` | Off | Boot, normal session end | Physical arm enters OBSERVE |
| `OBSERVE` | Off | Physical arm with valid policy and calibration | Explicit physical confirm enters ARMED; mute enters MUTED |
| `ARMED` | Ticket controlled | Physical confirm, consent valid, no fault | Session end enters DISARMED; mute enters MUTED; fault enters FAULT |
| `MUTED` | Off | Button, voice stop, WebUI stop, MCP mute | Physical acknowledgement enters DISARMED only |
| `FAULT` | Off | Watchdog, integrity, power, policy, persistent state, or driver fault | Maintenance plus physical acknowledgement enters DISARMED after self test |

There is no network, MCP, HOMECORE, voice, or model transition into ARMED and
no remote transition out of MUTED or FAULT.

While a session is armed, a dedicated broker liveness signal reaches an MCU
timer at least every 25 ms. The initial timeout is 75 ms and is verified by
benchmark S05. RPC health telemetry may run more slowly and is not the hard
shutdown mechanism. A liveness signal never extends a ticket beyond its signed
expiry and never opens an output by itself.

## 9. Arduino Router RPC

The Linux adapter connects to the documented Unix socket
`/var/run/arduino-router.sock` and uses MessagePack RPC REQUEST and RESPONSE
messages. Safety relevant calls MUST receive a response. They MUST NOT use the
fire and forget NOTIFY form.

| Method | Direction | Request | Response |
|---|---|---|---|
| `dream.edge.v1.capabilities` | Linux to MCU | Empty | Contract version, device, boot, firmware, policy, arm state, driver health, limits |
| `dream.edge.v1.time.challenge` | Broker to MCU | Broker request identifier | Single use challenge, MCU boot identifier, receive and send monotonic times, maximum uncertainty |
| `dream.edge.v1.sensor.latest` | Linux to MCU | Last seen sequence | Zero or more bounded `SignalFrameV1` summaries |
| `dream.edge.v1.heartbeat` | Broker to MCU | Broker boot, sequence, monotonic time | Receipt with health and arm state |
| `dream.edge.v1.cue.submit` | Broker to MCU | One CBOR `CueTicketV1` byte string | One `CueReceiptV1` |
| `dream.edge.v1.mute` | Any authorized local safety client to MCU | Registered reason | Receipt and immediate MUTED transition |
| `dream.edge.v1.receipt.after` | Linux to MCU | Last receipt sequence, maximum count | Bounded ordered receipt batch |

Each request is at most 4096 bytes. A sensor or receipt batch is at most 16
items. The adapter uses a unique request identifier, a bounded timeout, and
explicit reconnect behavior. A timeout is failure, never implied success.

Arduino Router has no documented deterministic latency guarantee. The system
therefore measures every request latency and performs final timing on the MCU.

## 10. Actuator contracts

### 10.1 Audio

The first supervised sleep cue uses a short immutable asset stored in MCU
controlled flash and rendered by a bounded timer or audio peripheral. The MCU
verifies its digest, selects it from the active policy, controls the low voltage
amplifier enable, and closes the gate at ticket expiry. Maximum analog gain is
physically calibrated so a full scale sample cannot exceed the approved sound
ceiling at the reference position.

Content rich or Linux rendered audio is not sleep cue conformant until an MCU
controlled content path, such as a digest verified external flash and audio
peripheral, prevents asset substitution by the Linux renderer. Linux and USB
audio remain valid for awake preview only. HomePod is not an implementation of
this contract.

### 10.2 Light

The MCU drives a warm source through a current limited stage. Policy maps
`intensityQ15` to a calibrated lux curve. An ambient light sensor detects a
stuck or externally illuminated condition. Fast strobe patterns and assets not
in the allowlist are impossible in v1.

### 10.3 Haptic

The MCU controls both waveform selection and a separate enable. Policy maps
normalized intensity to measured acceleration at the reference fixture. The
reference design uses a low mass, low voltage actuator under a mattress or in
a bedside object, never attached to the head or neck. Haptic remains disabled
until the audio only phase is complete and its own safety evidence is promoted.

## 11. HOMECORE adapter

The adapter composes the upstream RuView HOMECORE capability and does not
reimplement its state engine. It publishes derived entities with source,
confidence, quality, clock uncertainty, evidence level, and last update.

| Entity | Access |
|---|---|
| `sensor.dream_respiration_rate` | Read only |
| `sensor.dream_heart_rate_estimate` | Read only |
| `sensor.dream_signal_quality` | Read only |
| `binary_sensor.dream_bed_presence` | Read only |
| `binary_sensor.dream_cue_armed` | Read only |
| `sensor.dream_policy_version` | Read only |
| `event.dream_cue_receipt` | Read only event |
| `button.dream_stop` | Safety favored stop |

Wasm plugins receive read only state plus a capability to submit
`CueProposalV1`. They never receive the Arduino Router socket, cue issuer key,
policy install path, raw RF store, or actuator devices.

## 12. MCP surface

### 12.1 Transport

The server implements stdio for a client launched local process and Streamable
HTTP for the WebUI and Codex desktop. The HTTP endpoint is
`https://127.0.0.1:8900/mcp` on the UNO Q and is reached through an SSH tunnel.
It returns JSON or request scoped SSE as defined by the implemented MCP
protocol version. A permanent legacy `/sse` listener is off unless a development
flag explicitly enables it.

Same device clients MAY use newline delimited JSON RPC over a Unix domain
socket as a documented custom transport. They must preserve MCP message and
cancellation semantics.

HTTP authorization uses a short lived audience bound local capability. Tokens
issued for another service are rejected and never passed through. The server
binds to loopback, validates `Host` and `Origin`, rate limits requests, limits
body size, and records tool calls without recording secrets or raw signals.

### 12.2 `ruv://` resources

The canonical resource and tool registry is
[`mcp-registry.json`](./mcp-registry.json). The tables below summarize that
machine readable file. A conflicting prose name or URI is invalid.

The registry defines four principal classes: `local_human`, `local_service`,
`local_model`, and `cloud_model`. Any client that transmits request or response
content to remote inference is a `cloud_model`, including Codex Desktop unless
that exact session is proven to use only local inference. P0 is available to all
classes. P1 is local by default and requires an explicit short-lived human grant
for a cloud model. P2 is limited by default to local humans and services, may be
granted to a local model for one bounded session, and is always denied to a
cloud model. P3 is denied to every model. A tool's allowed-principal list cannot
override the privacy-class audience policy of its arguments or results.

In `mcp-registry.json`, `modelVisibleByDefault` means visible to a scoped
`local_model` only. It never implies cloud visibility. The authorization engine
intersects principal class, privacy audience, tool scope, resource scope,
purpose, profile, and expiry on every request and subscription.

The `ruv` custom scheme follows RFC 3986. The authority is exactly
`dream-machine`, and the first path segment is exactly `v1`. Path segments are
UTF 8 after strict percent decoding and may not contain slash, backslash, dot
segments, control characters, or an empty identifier.

| Template | Content | Default privacy |
|---|---|---|
| `ruv://dream-machine/v1/devices/{deviceId}/status` | Hardware, firmware, policy, arm state, driver health | P1 |
| `ruv://dream-machine/v1/subjects/self/consent/current` | Redacted current consent state and epoch | P2 |
| `ruv://dream-machine/v1/subjects/self/nights/{nightId}/summary` | Derived night outcomes and coverage | P2 |
| `ruv://dream-machine/v1/subjects/self/nights/{nightId}/signals/{windowId}` | Bounded derived signal window | P3 |
| `ruv://dream-machine/v1/subjects/self/nights/{nightId}/apple-watch/summary` | Authorized retrospective summary | P2 |
| `ruv://dream-machine/v1/subjects/self/nights/{nightId}/apple-watch/quality` | Coverage, delay, and revision quality | P2 |
| `ruv://dream-machine/v1/subjects/self/apple-watch/sync-status` | Bridge availability and sync state | P1 |
| `ruv://dream-machine/v1/experiments/{experimentId}/protocol` | Frozen protocol and allocation metadata | P1 |
| `ruv://dream-machine/v1/policies/active` | Public fields and digest of the active policy | P1 |
| `ruv://dream-machine/v1/candidates/{candidateId}/receipt` | Candidate verdict and human promotion status | P1 |
| `ruv://dream-machine/v1/cues/{ticketId}/receipt` | Cue decision and commanded gate evidence | P2 |
| `ruv://dream-machine/v1/evidence/{digest}` | Digest addressed evidence metadata | P2 |
| `ruv://dream-machine/v1/benchmarks/latest` | Latest signed benchmark summary | P1 |
| `ruv://dream-machine/v1/schemas/{name}/{version}` | JSON Schema and semantic documentation | P0 |

Resources use `application/json` and include `schemaVersion`, `observedAt`,
`source`, `confidenceQ15` when meaningful, `evidenceLevel`, and `privacyClass`.
Device status and the active session summary MAY support MCP resource
subscriptions. The server validates authorization on every read and
subscription. A missing or forbidden private resource is not represented by
fabricated empty contents.

### 12.3 Registered tools and model subsets

| Tool | Allowed principals | Effect | Actuation authority |
|---|---|---|---|
| `dream_status` | All; cloud requires explicit P1 grant | Read health, quality, policy digest, and physical arm state | None |
| `dream_session_query` | Local human, service, or model | Read a bounded derived summary or timeline | None |
| `dream_memory_search` | Local human, service, or model | Search redacted local RuVector summaries | None |
| `dream_intention_set` | Local human or service | Store an awake, locally confirmed intention | None |
| `dream_report_record` | Local human or service | Store a morning report revision | None |
| `dream_experiment_preview` | All, subject to input audience | Run deterministic replay against a proposed parameter set | None |
| `dream_cue_propose` | Local human, service, or model | Store one untrusted `CueProposalV1` and return a policy explanation | None |
| `dream_mute` | All authenticated principals | Request an idempotent transition toward MUTED | Stop only |
| `dream_receipt_export` | Local human or service | Create a user approved evidence export | None |

The MCP server MUST NOT register a tool that arms, resumes, executes a cue,
changes a safety value, installs a bundle or firmware, reads a signing key, or
promotes a candidate. Tool lists are deterministically ordered and may narrow
with authorization, but an unauthenticated request never gains a broader list.
Stop only authority can deenergize or shorten output; it can never arm, resume,
extend, select, or increase output. Apple bridge tools are optional profile
extensions in the same canonical registry and require separate scopes.

### 12.4 Example model flow

This example uses a `local_model`. A cloud model receives only P0 data and
explicitly granted, redacted P1 data; it cannot execute this P2 flow.

1. Read `ruv://dream-machine/v1/devices/{deviceId}/status`.
2. Read `ruv://dream-machine/v1/policies/active`.
3. Search redacted summaries with `dream_memory_search`.
4. Test a bounded idea with `dream_experiment_preview`.
5. Submit `dream_cue_propose`.
6. Receive a proposal identifier, policy comparison, and status such as
   `recorded`, `ineligible`, or `awaiting_broker`.
7. Observe any separately brokered outcome through the receipt resource.

The model never receives a cue ticket or direct device handle.

## 13. EvolutionCandidateV1

[`evolution-candidate.schema.json`](./evolution-candidate.schema.json) is the
canonical JSON envelope for a single bounded candidate. It binds the parent,
active signed envelope, immutable evaluation contract, evidence, expiry, and
rollback target. The candidate cannot select its own fitness gates.

The schema limits each candidate to one typed mutation. A deterministic
semantic validator MUST additionally prove that feature vectors retain the
declared dimension, a timing bin remains inside the signed opportunity window,
a cue belongs to the awake previewed library, minimum spacing only increases,
maximum intensity only decreases, and representation or compute changes cannot
alter the safety result. `authorityDelta: none` is a claim to verify against the
active capability graph, not proof of safety. Every promotion remains an awake
human decision.

## 14. Privacy and retention

1. The default runtime has no cloud endpoint and needs no WAN connection.
2. Each persisted record is assigned P0 public, P1 internal operational, P2
   personal, or P3 intimate. S0 is a separate secret class for keys, tokens,
   and recovery material and is never valid as an observation privacy class.
3. RuVector stores local embeddings and derived episodes on an encrypted
   volume. Raw journal text requires separate opt in and is excluded from model
   context unless explicitly selected in the local UI.
4. Profile export is user initiated, encrypted, purpose labeled, and contains a
   manifest. It never includes device or issuer private keys.
5. Profile deletion removes the data encryption key, vector index, summaries,
   raw calibration buffers, and pending proposals. The evidence ledger keeps
   only the minimum nonidentifying deletion receipt selected by policy.
6. Logs contain identifiers, hashes, status, and reason codes, not raw
   biometrics, utterances, or audio.

## 15. Packaging and deployment contract

The Mac Studio produces one signed, content addressed ARM64 bundle with:

1. Pinned HOMECORE and RuView binaries or images.
2. Dream Machine edge services and their exact dependency lock.
3. STM32 firmware and flash metadata.
4. Approved models, cue assets, and `SafetyPolicyV1`.
5. SPDX or CycloneDX SBOM.
6. Checksums, build provenance, signer identity, and minimum compatible
   contract version.

Bundle verification happens before installation. Activation is atomic between
two release slots. The previous verified slot remains available. A failed
signature, digest, compatibility, free space, self test, or firmware handshake
leaves the current slot active.

The Debian release uses separate systemd service users. Only the router adapter
can open the Arduino Router socket. Only the audio renderer can open the audio
device. Only the cue broker can access the issuer key operation. Services bind
to loopback by default and run with a read only filesystem view, private
temporary directory, explicit writable paths, no new privileges, bounded
resources, and a syscall profile appropriate to the implementation.

ADB is disabled after provisioning. SSH is disabled outside a maintenance
window or restricted to key authentication and local tunneling. No production
secret is passed through a Codex prompt, repository file, process argument, or
browser console.

## 17. Hardware in the loop plan

### 17.1 Independent witness

The HIL witness is electrically and logically separate from the UNO Q. It
connects to the Mac by USB and records:

1. Amplifier enable and acoustic onset with a calibrated microphone or sound
   level front end.
2. Light gate and lux with a dedicated sensor.
3. Haptic gate and acceleration with a dedicated accelerometer.
4. Power rail, reset, watchdog, and physical button state.

The device under test cannot write witness results. The Mac runner hashes raw
witness traces and binds the benchmark report to the tested commit, firmware,
policy, calibration, and hardware revision.

### 17.2 Required HIL scenarios

1. Valid ticket for every enabled modality at minimum, nominal, and maximum approved
   parameters.
2. Every reject reason in `CueReceiptReasonV1`.
3. Linux process kill before, during, and after a cue.
4. Router disconnect, duplicate response, delayed response, and MCU reboot.
5. Power interruption and brownout at output onset.
6. Physical mute at each cue phase and physical rearm behavior.
7. Corrupt MCU audio asset bytes, digest mismatch, peripheral hang, and stuck gate.
8. Stuck light driver and stuck haptic driver fault detection.
9. Eight hour sensor and service soak with network loss and restoration.
10. Twelve hour operation with the WAN physically disconnected and a packet
    capture proving no destination outside the configured local subnet.

### 17.3 Sensor validation

A low cost mechanical breathing phantom verifies geometry, transport, clock,
and frequency extraction. It is not biological accuracy evidence. Biological
validation uses a separate consented reference device and a predeclared
analysis. The MR60BHA2 output remains observational if it misses the coverage
or error target in ADR-0101.

Fans, moving curtains, reflective metal, water motion, pets, a second person,
bed vibration, and empty room runs are separate fixtures. Results report
abstention and coverage as well as error; filtering out failed windows after
the fact is not permitted.

## 18. Conformance and acceptance

The frozen executable inventory covers `SignalFrameV1`, `CueProposalV1`, the
JSON audit representation of `SafetyDecisionV1`, `EvolutionCandidateV1`, and
the MCP registry. It is intentionally a partial contract inventory, not a
conformant implementation. PR 2 must supply schemas for `SafetyPolicyV1`,
`CueReceiptV1`, each MCP resource envelope, and the evidence bundle manifest;
the Apple bridge PR must supply its message schemas before that bridge compiles.
Canonical CBOR and Protocol Buffer wire formats use golden vectors and separate
semantic validators where JSON Schema cannot express ordering, clock,
signature, cross-field equality, or monotonic mutation relations.

An implementation is Edge Contract v1 conformant only when all of these are
true:

1. JSON Schemas exist for every public JSON structure and reject unknown
   safety fields.
2. TypeScript, Rust, and STM32 implementations pass the same committed
   deterministic CBOR and Ed25519 golden vectors.
3. The MCU parser survives at least 1,000,000 malformed or fuzzed tickets with
   zero unauthorized output transition.
4. Ten thousand replay cases actuate at most once per unique valid ticket.
5. Power, reset, heartbeat loss, and every fault path close all gates within
   the bounds in ADR-0101.
6. HIL witness results prove timing and physical output bounds; MCU self report
   alone is insufficient.
7. The registered MCP tools and resources match this document exactly or form
   a strict, safer subset.
8. MCP URI, authorization, cancellation, size, origin, and rate limit tests
   pass for each enabled transport.
9. RuVector failure, missing optional sensors, and WAN loss remain safe and
   produce explicit degraded status.
10. The signed bundle, SBOM, install, health check, atomic activation, and
    rollback tests pass on the 4 GB UNO Q.
11. Dependency, secret, static, fuzz, network exposure, and threat model scans
    have no unresolved confirmed critical or high finding.
12. Every quantitative claim links to a report with raw receipt location,
    method, sample count, environment, uncertainty, and exact artifact hashes.

Until all twelve items pass, the implementation identifies itself as
`edge-v1-prototype`, never `edge-v1-conformant`.
