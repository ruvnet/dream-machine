# Hugging Face background rule learning

Experimental adapter for PR168. It generates a bounded rule from public or synthetic training observations, tests training consistency locally and asks for repair at most twice (three total calls). It keeps the deterministic proposer as fallback. It never runs arbitrary generated code, exposes hidden evaluation data or promotes a rule. This is bounded proposal refinement, not model weight training or demonstrated recursive self improvement.

Build with `npm run build -w @dream-machine/compile`. Run `node --test scripts/hf-rule-learning.test.mjs`. With an existing authorized HF_TOKEN secret binding, run `node scripts/run-hf-rule-learning.mjs observations.json config.json`.

The observation file is an array of `{state:{x:1},action:2,nextState:{x:3}}` transitions. Configuration requires model (`organization/model`), an explicit provider, maxCostUsd, inputUsdPerMillion and outputUsdPerMillion verified from current provider pricing. Optional maxCalls defaults to 2 (maximum 3), maxOutputTokens 512 (maximum 2048) and timeoutMs 15000 (maximum 60000). No price or model availability is assumed by the implementation. Test fixtures use illustrative prices, never a live quote.

Spending reservation uses input payload bytes plus a 4096 token protocol allowance and requested maximum output tokens. This is a conservative estimate, not a billing guarantee. Use a provider/account spending limit as the authoritative cap, verify tokenizer and provider billing semantics before paid use, and reconcile billed usage externally. Failed requests retain their reservation. No retries after transport failures. Candidate validation or training disagreement can use the remaining configured repair rounds. No new dependencies or endpoint provisioning.

Threat boundaries: the token goes only to the fixed HTTPS Hugging Face router; redirects fail. Error details are suppressed. Response bodies are bounded at 64 KiB and requests have an abort deadline. Candidate schema and safe integer operations are independently validated by the existing interpreter. Caller must classify observations as permitted for provider disclosure. Training receipts are not hidden evaluation evidence. Hosted model regeneration is not guaranteed deterministic; capture candidate artifacts and replay locally.

Pass returned candidates into the independent MetaHarness evaluator from PR394, using evaluator-owned untouched tasks; signed promotion remains with Autogenous PR19. Do not feed final holdout failures back into this learning loop. The two identical training arrays used internally are solely a training consistency check, not two independent datasets. Final acceptance remains a 20 percentage point gain on two of three distinct tasks, no family regression, 25 percent fewer environment interactions, independent probes and exact replay. Count inference tokens and total cost separately.

Validation on 2026-10-11: ten mocked transport tests cover proposal, repair, budget exhaustion, missing credentials, unsupported operations, rate limiting, oversized/malformed output, routing and timeout. Live inference is blocked because this workspace has no HF_TOKEN binding. No measured model quality, spend or latency claim is made.

## Persistent cycle and ruOS execution

`node scripts/hf-learning-cycle.mjs spec.json evidence-directory` runs up to three tasks, each with separate training/confirmation arrays and a strong baseline RuleCandidate. The spec includes schemaVersion 1 and the adapter config. Baseline and confirmation validation precede network activity. Input overlap is rejected. The same immutable spec reuses its integrity-checked receipt without another inference call. An exclusive lock prevents simultaneous writers; a crashed lock requires operator inspection, never automatic deletion. To retry a blocked run, revise the explicitly versioned spec after fixing its cause. Do not tune against the same confirmation set.

`python3 scripts/ruos-hf-run.py spec.json evidence-directory` uses the desktop's owner-only binding with no symlink following and passes only HF_TOKEN plus minimal PATH/HOME to the trusted runner. It does not pass npm/PyPI/cloud tokens. Execute in an owned isolated directory with reviewed source. Artifacts remain local to the existing authorized executor; the wrapper does not change vault settings.

Each result retains candidate, hashes, local exact checks, strong baseline and deterministic search scores, model attempts, latency and token usage. NO_GAIN outcomes remain first-class records. EXPERIMENTAL_GAIN means only superiority in that particular frozen fixture; no production promotion or signed gate evidence is emitted. These artifacts can be submitted to the independently reviewed MetaHarness/Autogenous path. Their multi-task and interaction-savings requirements are not replaced by this runner.

This implements persistent experiment state and bounded proposal repair, not weight training, automatic deployment or universal self improvement. New task specifications and confirmation sets remain evaluator-owned. No private data goes to an external model by default. The earlier missing-token note describes the initial workspace only; ruOS binding and live Groq inference were subsequently verified. Explicit User-Agent identifies this client after the Python prototype observed transport differences.

## Actual adapter experiment, October 11

The real adapter was executed on ruOS Node 20.20.2 with the Groq route. Earlier scalar JSON smoke results did not transfer directly to the program schema. Retained live receipt: `hf-live-cycle-20261011.json`. The normalized wire response returned HTTP 200 but failed local operation validation; a bounded repair returned HTTP 400. No candidate was eligible. The strong baseline passed 20/20. The experiment validates fail-closed rejection, not useful learned improvement. Several schema/transport debugging attempts were made; receipt tariffs are reservations, not all-attempts billed cost. Final source also binds source bytes into receipt cache identity and retains usage from invalid responses; that final instrumentation was locally tested after the live attempt.

The provider wire schema uses fixed nullable value/from fields, independently normalized to the existing interpreter operations. It never expands that interpreter. Model schema adherence cannot replace local validation. The next experiment must resolve provider output compatibility on training-only fixtures before spending on a new untouched task evaluation. Reuse prior failure receipts instead of treating the earlier simple JSON response as complete integration. No production learning is enabled by a local research verdict.

## Demonstrated narrow benefit, October 11 follow-up

Compatibility recovered with explicit JSON object mode, low reasoning effort, a 2048 token output allowance and a prompt specifying whole-state mutation. These settings are opt-in (`responseMode`, `reasoningEffort`); local validation remains unchanged. The combined change passed the actual adapter, but this experiment does not isolate which change caused recovery. Groq documents JSON object mode and strict schema limitations at https://console.groq.com/docs/structured-outputs.

The model learned a file framing size rule from four real filesystem observations. Twenty separate confirmations admitted it to a research-only surrogate. On 1,000 additional inputs the retained rule matched 1,000 real filesystem results and replayed exactly 1,000 times. Operational environment calls fell from 1,000 to 124, including 24 setup calls and 100 periodic audits, a reduction of 87.6%. Measured time was 39,591 ms for direct environment queries versus 9,929 ms for learning, setup and local serving combined, a reduction of 74.9%. Request p95 was 160.49 ms versus 27.05 ms. Measurements are one run on ruOS Node 20.20.2, not a device-wide guarantee. Separate reference calls used to measure correctness are additional experimental cost, not part of the proposed serving path. Earlier failed development attempts are excluded from per-candidate amortization.

The successful proposal used 369 prompt and 721 completion tokens, approximately $0.000488 at the checked tariff, excluding failed attempts and provider billing adjustments. Actual billed cost remains unverified. The SQL batch candidate was rejected after two invalid programs and is not a success. A hand-authored arithmetic formula also scored 1,000/1,000. This demonstrates a narrow automatic observation-to-surrogate efficiency improvement over repeatedly calling the environment, not superiority over analytic code, weight training or the broad multi-task acceptance gate.

`validated-rule-cache.mjs` requires confirmed evidence, explicit bounds and a scope identity. Changed scope or out-of-range input uses the oracle. Every tenth supported request is audited. A mismatch revokes the rule and returns the oracle result. An injected change was detected and revoked in the earlier 100-query trial. Up to nine changed-environment predictions can occur before an audit, so adoption remains shadow-only. Never apply this surrogate to authorize actions, skip side effects, replace writes or make safety-critical decisions. It predicts outcomes only.

Decision: retain this as a research efficiency result. Next require two genuinely distinct workload families, lifecycle identity binding and zero unsafe outputs under injected drift before production adoption. Existing MetaHarness and Autogenous gates remain authoritative and unmet.
