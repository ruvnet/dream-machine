## Decision

Retain the draft PR and human review boundary. Implement the substantiated
repository defects now; keep physical cueing blocked until independent safety
isolation and all device specific acceptance gates pass.

The review used one integration owner and three independent workers for
contracts, merge governance, and architecture. Ruflo 3.25.6 coordinated the
swarm and security assessment. Each worker had exclusive file ownership; the
coordinator reviewed the returned diffs and ran the combined tests. SPARC gates
were compressed into requirements, contract invariants, bounded corrections,
and executable acceptance. No worker merged, deployed, flashed, or actuated.

## Findings and disposition

| Priority | Confirmed finding | Correction and evidence |
|---|---|---|
| P1 | `autoMerge: false` was not read by the merge workflow; its path filter omitted new contracts and ADRs, and its file retrieval could truncate | Workflow now has only read permissions and no merge or label commands. Base configuration, complete pagination, rename sources, metadata freshness, and protected paths are checked by 14 native tests. Eligibility never grants merge authority. |
| P1 for live hardware | Stock UNO Q MPU software can program the integrated STM32, contradicting an unconditional independent verifier assumption | ADRs 0100 and 0101, threat T17, benchmark S13, and the runbook now require independent debug, flash, memory, and gate isolation evidence. An external safety controller is the fallback. This is a release blocker, not an alleged Arduino vulnerability. |
| P1 | Eight known dependency findings and an obsolete development runtime recommendation | Patched locked graph; supported Node 22 and 24 CI; dedicated dependency audit job. Full and production npm audits each report zero findings. |
| P2 | Root typecheck always failed on an empty configuration and CI only built packages | Root configuration now checks source and tests directly through workspace source mappings. CI runs typecheck before build. There is no failure masking fallback or P1 waiver. |
| P2 | An explicit RVF request could return flat keyword memory labeled `ruvector-rvf` | Explicit requests now fail with an unimplemented adapter error even when the optional module loads. Auto mode honestly reports `flat-file`; a new regression covers the misleading path. README and ADR updated. |
| P2 | A 64 byte signature schema accepted multiple base64url strings for identical bytes | Restrict the final character to `[AQgw]`; test canonical encodings, pad bit aliases, padding, length, and whitespace. This fixes canonicalization, not signature forgery. |
| P2 | Schema and registry checks existed only as one time review claims | Added strict offline AJV checks, positive and negative fixtures, semantic timing constraints, immutable authority ceilings, and graph derived plan checks to CI. |
| P2 | Thirty samples could not establish p99 and fourteen nights could not establish greater than 99 percent reliability | Require per operation samples, confidence bounds, dependence assessment, and inconclusive outcomes. The pilot and field reliability claims are separate. |
| P2 | 82 engineer days were advertised as 10 to 14 weeks for one engineer plus agents | Single engineer baseline is 16.4 weeks, approximately 20.5 with a 25 percent reserve. A staffed concurrent team's dependency lower bound is 10 weeks, not an agent productivity measurement. |
| P2 | A 70 night study conflicted with the ten percent generated exploration cap and positive results were required to finish P8 | Distinguish the frozen human study from generated candidates requiring at least 140 eligible nights for 14 exposures. Separate study completion from promotion and test both boundaries. |
| P2 | Serious thermal state had conflicting Watch stop instructions | ADR and benchmark consistently require live research collection to stop at serious or critical state. Actual device timing remains unmeasured. |

Arduino documents the MPU programming capability in
[remoteocd](https://github.com/arduino/remoteocd). Requiring an externally
isolated controller when stock isolation cannot be proven is this project's
design inference, not an upstream hardware certification.

## Limits, next gates, and rollback

1. The legacy `pull_request_target` workflow remains authoritative on the base
   branch until a human merges the reviewed change. Do not apply the automatic
   merge label during that transition. Inspect and cancel any previously pending
   automatic merges manually. Remote rulesets were not modified by this review.
2. P1 still requires the actual Mac fingerprint, Xcode and Arduino toolchains,
   provenance, SBOM and license evidence, development service isolation policy,
   and an independently verified offline build. This is partial P1 hardening,
   not completion of the ten phase system.
3. No physical device, HealthKit import, live Watch session, HomePod timing,
   native RuVector persistence, MCP authorization server, canonical CBOR parser,
   signature verifier, or sleep intervention was exercised.
4. Contract tests prevent reviewed architecture drift; they are not a million
   input production parser fuzz run. Signature and resource template validation
   is not cryptographic verification or a production URI resolver.
5. No comparative runtime speed, accuracy, battery, thermal or clinical gain is
   claimed. Performance acceptance requires the new sampling contract.
6. Revert changes through a reviewed commit if needed. Do not restore the old
   automatic merge workflow or vulnerable dependency graph as a shortcut;
   retain human review and isolate development while resolving a regression.

Acceptance test: on a fresh supported Node checkout, `npm ci && npm run check`
must pass all 140 tests and the contract gate. Physical cueing remains blocked
until the exact controller passes T17 and S13 with actuator power disconnected.
